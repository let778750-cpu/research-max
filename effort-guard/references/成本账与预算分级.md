# 成本账与预算分级

本文件回答：预算写什么、写在哪、怎么记才不假装精确。原则：**能核对的记实际值，不能核对的标未知，绝不用看似精确的数字代替判断。**

## 一、四类成本

| 成本 | 记什么 | 常见漏记 |
|---|---|---|
| 时间 | 日历时长、占用的人的时间、等待外部反馈的时长 | 等待与排队；上下文切换 |
| 调用与算力 | token 用量、模型调用次数、GPU 或仿真机时、付费接口次数 | 重试、失败调用、嵌入与索引 |
| 人工复核 | 读、审、比对、决策所需的人时 | 复核两遍；为看懂生成代码花的时间 |
| 维护 | 下次改一处要动几处、是否要重跑、谁会读 | 新增抽象的理解成本；测试随结构失效 |

四类里最容易漏的是后两类，而它们恰是过度建设的主要代价。只记时间与 token，会得出"多写不花钱"的错误结论。

## 二、四档任务

| 档 | 判定 | 要填什么 | 例子 |
|---|---|---|---|
| 轻 | 单文件小改、一次查询、只读检查 | 一句停止条件 | 改个路径、查一条定义 |
| 中 | 多文件、多轮、要跑测试或反复调参 | 成本三格 + 修复尝试上限 | 修一个跨模块的 bug |
| 重 | 正式实验、批量复跑、付费调用、跨 Harness 派发 | 成本三格 + 2—3 条路线 + 检查点 + 回滚点 | 一次全量复跑 |
| 探索 | 选题、调研、方法发散、一次性原型 | 探索三格 + 每轮产出 + 探索额度 | 一个新方向的可行性摸底 |

判档宁低勿高：拿不准时按低一档做，做到一半发现超出再升级，并补记升级理由。反过来（先按重档填表）会让填表成本超过任务本身。

## 三、成本三格怎么写

**第一格 成功判据。** 写成"什么东西出现就算完"，不是"做好"。例：某脚本在给定输入上输出与参考一致的表；某段实验在指定条件下跑完并留下日志与结果文件。

**第二格 预算。** 三类各给区间：时长、调用或算力、人工复核。给区间不给点估计，因为点估计会被当成承诺。未知就写未知，并写"第一个检查点后补充"。

**第三格 停止条件。** 至少一条可判定的停止：判据满足、预算到点、或同一根因两次未修复。停止条件要写在开工前，事后补写等于没有。

## 四、探索三格怎么写

**问题**：这一轮想弄清什么，一句话。
**判别式停止**：什么情况下算"再查也不改变问题图"，例如"关键主张的最近邻与反证入口已覆盖"。
**每轮产出**：每轮留下什么可核对的东西（缺口清单、证据表、否定结论）。

探索额度（轮数、比例或时长）由项目给，技能不给通用数字；额度用完不等于探索充分，只说明该下判断了。

## 五、与既有记录的边界

- 正式实验的预算、费率、失败重试与删减次序，沿用 research-execution 实验协议对应条目，本技能不另立字段。
- token、耗时与费用的日常登记沿用 research-execution 协作与接续的"上下文与成本"，本技能只要求在汇报时引用，不重复记录。
- 同一笔费用只在一处记账，其他位置引用该处；发现两处数字不一致时，以凭证更全的一处为准并更正另一处。

本技能不新建台账，是因为第二本账必然漂移，而漂移的账比没有账更危险。

## 六、度量诚实

- 文件读取量、工具调用次数、对话轮次只是代理指标，不能换算成真实费用。
- 没有同条件的真实对照，不宣称"节省了多少百分比"。
- 免费额度、试用额度按实际支出记零，但要标注"额度内"，避免把免费期的成本结构当成长期成本。
- 汇率、费率与计价单位在记录时写明来源与日期；来源不明按未知处理。

## 七、反例

- 用"跑了 20 轮"证明投入充分，而不说 20 轮各自排除了什么。
- 预算写"尽量少"，等于没写。
- 成本记在聊天里不落盘，换窗口就丢。
- 只记成功的调用，漏掉重试与失败。
- 把维护成本写成"以后再说"：它不会消失，只会转给下一个人。
