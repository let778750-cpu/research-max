# 可选 Claude Code 单模块桥接

需要完整 research-max、Python 3.10+、已安装的 Claude Code，以及用户已配置的可用模型。程序不会安装CLI、修改全局设置或创建调度服务。研究与验收规则按名使用 research-execution 的“跨Harness任务执行”；此处只说明接口与实际机械保证。

## 何时运行

用户明确指定具体任务采用跨Harness方式后，主持者才使用本入口。讨论、认可方案、读取文件、普通任务、打开旧项目和查询历史均不启动模型。Markdown执行约定只是已有授权的记录，无法替代主持者检查真实用户指令，也不是防恶意调用的权限系统。

保留权威PLAN/TASKS与六种任务状态。桥接只保存尝试/进程事实，不更新任务状态，不执行最终验收，不自动发下一模块。已经开始的尝试绝不自动重放；同一项目同时最多一个运行；工作副本旁的原子占用目录也阻止不同权威项目同时写同一个副本。新窗口须经用户明确接续并核对占用。

## 准备

使用现有 research_infra.py 检查项目；桥接沿用 project.json 和 Markdown 任务源，需要实际负责人、V版本和验收条件。旧JSON检查与快照保持兼容，但桥接首版仅接收Markdown执行约定。默认同时发现TASKS.md和tasks.json时仍报歧义，使用 --tasks 明确选择。

用户指定范围后，在任务文件的独立二级标题“执行约定”下填写五项：

| 字段 | 写法 |
|---|---|
| 执行方式 | 跨 Harness |
| 指定任务 | 明确ID，以顿号或逗号分隔，不支持通配符 |
| 授权来源 | 实际用户指令摘要或可核对引用 |
| 当前接手者 | 本次主持者的明确标识 |
| 派发 | 允许／暂停／结束 |

只保留一份当前约定；历史调整写普通段落，不复制第二份可解析约定。完成选定范围后主持者将派发改为结束；暂时回到讨论时按用户意图决定暂停或让当前模块做完。

执行目录须为权威项目之外的独立工作副本，不能包含权威项目。Git项目可用独立worktree，再带入当前需要的未提交修改；不自动stash、reset或整目录覆盖。非Git项目复制明确工作文件即可。关键输入在两个目录中保持相同相对路径与字节，用 --input 逐一绑定；大数据按实际必要范围配置，不要求全项目复制。

准备项目内的Markdown实施说明，补充必读材料、方法约束、资源范围与停止条件。补充说明是任务要求之外的派发依据；变更它也需新尝试。不要在提示词或工作副本放密钥。

## 命令接口

以下为命令形状，尖括号内容必须替换；不是已执行示例。

```text
python bridge.py prepare --root <权威项目> --task <任务ID> --run <唯一尝试ID> --owner <当前接手者> --workspace <独立工作副本> --instructions <项目内说明.md> --input <关键输入相对路径> --write <允许修改相对路径> --model <执行模型ID> --timeout <秒数>
python bridge.py run --root <权威项目> --run <尝试ID> --owner <当前接手者>
python bridge.py status --root <权威项目> --run <尝试ID>
python bridge.py cancel --root <权威项目> --run <尝试ID>
```

prepare、status、cancel、release只操作本地文件；只有run调用模型。prepare和run分开，主持者可以直接阅读BRIEF.md。--input和--write可重复；没有write时只允许返回检查结果。目录write允许其子路径；禁止整个工作副本、路径穿越与链接目标。--timeout须为有限正数，为本次调用上限，不代表套餐计费上限；真实模型调用使用既有账户额度，主模型品牌和角色不认证实际服务端身份。

run为前台控制进程，可交给Codex的长时命令工具并查询同一次调用；无需可见终端。不为它额外建立无人值守服务。退出码：0为命令成功（run只表示可提交审核），1为运行未满足机械交付条件，2为参数/输入/前置条件错误。

修回在实施说明中写具体缺陷与允许变动，使用新的 --run，并在prepare指定 --resume-run <旧尝试ID>。只恢复相同任务、相同工作副本且已结束的尝试，使用明确会话ID；不存在会话ID时开启新尝试。新模块默认新会话。不要使用 --continue 猜“最近会话”。

审核意见的快速核实直接写进这次修回说明，和有效修复合并在同一次调用；无需先单独调用一次“检查审核者”。若只是非阻断建议且主持者已通过，不新增调用。何时复用证据、处理分歧和停止往返，按research-execution的“跨Harness任务执行”执行，CLI不替代这些判断。

对已完成模块做交叉核查时，当前CLI仍只派发待做/进行中的任务：复用或新增一张范围明确的复核卡，输入关联原任务要求和产物，用该卡的ID准备新会话，不恢复原作者会话，不将原已验收任务改成待做。复核卡不把被查结论通过作为依赖；其验收对象是核查报告。无--write时只读副本并在最终回复返回报告，程序把它保存到REPORT.md；确需生成小型检查输出时，只允许新的结果路径，原输入/代码不纳入写域。主持者随后绑定报告及原产物版本。用户指定的核查范围可承接到这张复核卡并记明对应关系，不能自动变成修复授权。

--parallel显式注册仅本次会话可用的module-worker并开放前台Agent工具；默认不开放，也不安装全局子代理。本机实测bare模式即使传入--agents仍仅提供基础工具，因此并行模式使用项目专属CLAUDE_CONFIG_DIR、空setting-sources、禁用hooks/自动记忆及排除自动指令加载的会话设置，显式注册--agents。配置不写入用户全局目录。串行和并行不能互相恢复旧会话；切换时开启新会话。首版关闭实验性Agent Teams，以前台子代理实现有界并行。只有模块确有独立产出才启用，提示词须分清写入范围；所有子代理必须在本次结束前收尾。

## 运行与返回记录

权威项目的 .research-harness/runs/<尝试ID>/ 保存：BRIEF.md、dispatch.json、binding.json（生成的派发与版本清单）、started.json（启动占用证据）、runtime.json（运行事实）、events.jsonl（筛选后的事件元数据）、REPORT.md（实际最终回复）、必要的stderr.txt。它们不是新任务库；不要手工编辑生成记录。失败尝试保留，不用同ID覆盖。active/只存项目运行占用；工作副本相邻的.research-harness-<路径摘要>.lock/记录共享副本占用，正常结束时删除。占用记录与任何历史任务状态分开。

串行调用使用Claude Code --bare；并行使用上述项目专属配置。提示词通过stdin传入，argv不拼shell命令；仅传当前模块必要工具，禁用自动记忆与hooks、仅连接显式空MCP配置，并排除普通自动发现的指令文件。组织托管策略仍由CLI执行，不承诺覆盖它们。必须由主持者把适用项目约定写入实施说明或列为明确材料。既有用户设置中仅读取Anthropic端点/鉴权与模型映射等小范围环境项到进程内存，不复制整个配置；不修改用户设置。环境变量优先于用户设置。鉴权依赖API key/token；不承诺bare模式支持Claude订阅登录。

日志保留事件类型、会话、报告的模型名、实际工具调用名与结束信息，不保存思考、工具参数、环境转储。已知凭据值从回执和错误输出脱敏；这不保证识别任意未知敏感数据。完整Claude会话转录由CLI自身按其规则管理，桥接不复制它；并行模式转录位于项目的.research-harness/claude-profile。不要把包含原始会话的目录未经核对直接发布。

收到唯一成功结果事件、退出码为0、回执身份/要求匹配、报告完成且子作业结束、输入与当前要求仍有效、工作副本无范围外改动时，才给 ready_for_review=true。结果为部分完成/受阻、缺少结果、非零退出、重复结束事件、旧依据和残留子进程均不满足。status会再次检查证据是否已改变。它不评价科学结论，不证明自检真的执行，也不替代主持者的独立检查。

主持者收到返回后检查产物，将实际自检和产物摘要写入任务卡并置待核验；验收通过后再记录已验收。桥接不帮执行者签署验收。整合到权威项目时核对当前基线，保留他人修改；对整合后的实际文件绑定最终验收。

## 停止与恢复边界

cancel只写取消请求，控制进程观察后终止自己拥有的进程树；再用status核对实际状态。Windows使用Job Object，目标CLI在归入Job之前不会启动；正常CreateProcess子代随Job管理，控制进程崩溃时由系统关闭Job。POSIX使用进程组，控制进程被强制杀死后的残留需要核查。WMI、远端服务、脱离进程组的作业不受上述保证覆盖，首版不允许启动。

主调用结束后若仍有普通子进程，桥接清理它们并拒绝报告机械完成。提示词与Job Object不是文件系统或网络沙箱；只核查声明输入及工作副本，不能认证未声明依赖和其他目录从未变化。不要对不可信代码宣称隔离安全。

控制进程已经退出而active占用残留时，先核对回执和产物，再使用：

```text
python bridge.py release --root <权威项目> --run <尝试ID>
```

release要求记录的控制与直接运行进程均不存活；无法核清时不自动抢占。它只解除占用，不续跑、不验收。取消、超时或未知结果后，先判断实际效果再新建尝试，避免重复昂贵实验。准备后工作副本改变时也要新建尝试。


测试用隔离临时目录和模拟CLI，不调用模型，不改用户配置。真实模型验证应另用明确标注为示例的任务、小预算和独立工作副本；串行闭环通过后再测前台子代理。原有离线检查测试照常运行。
