# Zotero 中文对照 0.3.6

单击“翻译”完成本机存档检查、缺漏识别、翻译、整份 PDF 排版和原附件更新。插件与服务配套为 0.3.6。新版本按完整语义段落归并原字符及脱离正文绘制的数学对象，避免 PDF 绘制碎片被当成独立段落后无法排版。所有成功译文直接写入同一中文 PDF，不增加补译面板或可见附件。已有 OCR、段落译文和密钥继续复用。实际覆盖与局限见 [验收记录](docs/ACCEPTANCE.md)。

## 安装与密钥填写

1. 解压运行包，运行 `install-runtime.ps1`；服务安装到独立运行目录，保留上一版供回退。
2. Zotero“工具 → 插件 → 右上角齿轮 → 从文件安装插件”，选择配套 `research-max-bilingual-0.3.6.xpi`。
3. 打开 **工具 → 中文对照设置**，在第一栏 **AI Studio 访问令牌（PaddleOCR API Key）** 粘贴飞桨 AI Studio 令牌，点击 **保存**。留空不会清除已有令牌。此处使用 AI Studio 访问令牌，不是百度智能云 OCR 的另一种 AK/SK。
4. 下方保留已有翻译服务商、模型和标准 API 密钥。默认智谱 `glm-5.3-flash`，可手动切换 DeepSeek。插件不读取或改写 Claude Code 配置。
5. “检测飞桨连接”只查询身份，不上传论文；首次实际翻译才验证所选模型及返回结构。已经保存的令牌无需重新填写。

选定 PDF 会发送至飞桨 AI Studio 解析；待译文本发送至配置的翻译接口。两种凭据分别使用 Windows DPAPI 加密，只适用于当前 Windows 账户。源码、安装包和日志不包含凭据或私人论文。解析额度与翻译接口额度分别计算，以服务商账户记录为准。

## 日常使用

- PDF 工具栏单击“翻译”，按钮立即进入工作状态；运行期间为“取消翻译”。取消保留进度，不交付半成品。重新点击查询已提交的远端 OCR 任务并复用已保存译文。
- 新旧论文都使用同一个入口。完整且规则未变化的存档经过本机检查后直接复用；规则升级或发现可重试缺漏时，从原 PDF 重建结果并复用有效段落译文。空识别会实际重试对应空区域；当前排版规则已无法改善的局部会明确保留未完成数量，避免重复点击只产生相同修订。
- 同一原文维护同一个当前中文附件，校验、备份后原子替换，保留 Zotero 附件 ID。旧版本备份位于运行目录，不新建可见附件。不自动删除历史重复附件。
- 原文及批注不变。中文批注位置受影响时保留对应旧区域；无法得到局部位置的笔迹批注采用整页锚点。报告记录这些未更新区域，避免将它们计为完整翻译。
- 左右两个 PDF 共用物理页序，可调整宽度、同步或独立阅读。新增译文直接写入 PDF，页面下方没有补译面板。待核对菜单只定位问题区域。
- 可以提交多篇，最多两篇同时进行网络处理，本机排版串行。同一 PDF 去重；“工具 → 取消中文翻译任务”停止本次批量。每篇提示结束约 3.5 秒后关闭，再开始时立即移除旧提示。

## 识别与排版

PaddleOCR-VL-1.6 提供页面布局与内容类型；PyMuPDF 提取原文字形和坐标。有可靠原文字符时优先使用原字符。图中文字使用 PP-OCRv6 定位，表格使用 PP-StructureV3 单元格信息并核对原字符是否完整保留。每批最多 20 页、40 MB，核对返回页数和页码；不静默截断。

标题、摘要、正文、图表文字、符号说明与算法自然语言都进入清单。参考文献中可识别的引号题名可翻译，作者、刊名、DOI 等身份信息保留。复杂背景上的图中文字、无法准确分离的扫描公式、旋转文字等可能局部待核对，不用 OCR 猜测的 LaTeX 重画公式。

原页数、页面尺寸、双栏及图表位置保持；段落内部允许换行和使用同栏空白。普通斜体英文不因斜体被整段跳过。简单行内数学对象复制原 PDF 字形；可完整绑定的复杂行内公式同样复制原字形及矢量，算法中的公式保持原位、自然语言就地翻译；不能安全分离的局部保留并列入核对。排版区扩展不扩大可删除的源字符范围。中文字号下限为原段的 85%。

工具栏分别显示原生文字和图中文字的写入比例。覆盖统计基于统一清单中的待译原文词数，包含识别到的图表文字；纯公式、数字标识、保留的文献身份信息不在翻译分母内。未识别的图片页、低置信文字和未排入区域仍有待核对记录。此比例不是识别召回率或语义正确率，不保证任意论文绝对无误。

## 存放与缓存

源码只在本仓库 `integrations/zotero-bilingual` 中维护。插件由 Zotero 管理到用户配置目录；程序安装目录不放开发源码。

- `versions/0.3.6`：独立 Python、锁定依赖、本机服务、字体及许可证。
- `data/config`：设置、GLM 的 `credential.dpapi`、飞桨的 `paddle-credential.dpapi`。
- `data/cache/ocr`：云端解析结果与远端任务编号；不保存令牌或签名下载 URL。
- `data/cache/layout`：按原文件哈希、识别模型及规则版本保存的内容清单。
- `data/cache/text`：按原文、翻译模型、语言、术语和提示规则保存的段落译文。
- `data/cache/<指纹>`：最终 PDF 与质量报告，长期保留。
- `data/jobs`：可恢复任务和过程文件；成功导入后清理该任务的临时论文副本。
- `data/backups`：附件更新前的 PDF、批注与报告快照。

同一 PDF 改名或出现在其他条目时按文件 SHA256 复用；不按题名猜测同一文件。旧版缓存保留用于迁移，升级后第一次点击仍执行新识别清单，不能沿用旧排除区域来假称完整。已提交的云端解析没有公开取消接口，取消仅停止本机后续工作；再次启动先查询远端结果。限流退避、额度耗尽暂停，不自动切换付费产品。

## 开发与发布

Node.js/npm 用于构建 XPI；Windows Python 3.12 用于本机服务。运行使用 `-I -B`，依赖锁见 `server/requirements.lock`。

```powershell
npm ci
npm test
npm run build
python -m unittest discover -s tests -p 'test_*.py'
```

`scripts/build_runtime.py` 从指定 Python 3.12 与字体目录构建独立环境，默认使用锁定依赖。`scripts/package_release.py --runtime <运行目录>` 生成 XPI 配套运行 ZIP、源码包、依赖清单及 SHA256；禁止打包重型推理框架、数据、密钥和论文。已发布版本目录不直接改写。来源与许可见 [licenses/README.md](licenses/README.md)。旧引擎代码仅供历史迁移和回退，不在默认翻译流程中加载。

回退时安装保留的 0.2.3 XPI，并让 `active.json` 指向对应运行版本。卸载插件会停止服务，保留已导入译文、批注和本机存档；清理数据需用户另行明确操作。
