# 结论优先汇报结构

本文件是 T1、T2、T3、T6 的执行细则：一段汇报怎么开头、怎么组织证据、边界放哪、写多长。病灶判据见[过度防御表述诊断与改写](过度防御表述诊断与改写.md)，缩写格式见[缩写与术语首现规范](缩写与术语首现规范.md)。

## 一、四段骨架

| 段 | 内容 | 长度 | 禁忌 |
|---|---|---|---|
| 判断 | 做了什么、结论是什么、能不能用 | ≤5 行 | 复述需求、自我介绍、预告"下面分几点" |
| 证据 | 每条判断一到两个锚点：文件与行号、数值与单位、命令、结果路径、测试或回放名 | 每条判断 ≤120 字 | 无锚点的形容词、过程流水账 |
| 边界 | 局限、未做、未验证、外部依赖，固定标题"边界与未做" | ≤5 行 | 同一免责重复出现、把边界写进每段 |
| 下一步 | 只在有具体动作时写，一到三条，可执行 | ≤3 行 | "如有需要我可以……"式兜底 |

四段不一定都出现：短问答只需判断与依据；失败汇报把"判断"换成"没做成什么、为什么"。

## 二、篇幅参考

判断条数是分母，字数是结果，不是目标。

| 任务类型 | 参考篇幅 | 组织方式 |
|---|---|---|
| 单点问答、是否、路径确认 | ≤150 字 | 一句判断加一行依据 |
| 单文件改动、单条命令 | ≤300 字 | 判断、改动位置、验证方式、边界 |
| 多文件改动、实验、长排查 | ≤800 字 | 判断、三到六条判断各带锚点、边界、下一步 |
| 落盘报告、交付说明 | 按 report-writing 技能 | 先按本文件结构，再按其文体规则 |
| 用户明确要求详解 | 首段声明"应要求详解" | 可超参考值，结构不变 |

无新增判断时不扩写：删重复背景、删过程复述、删"我们首先、然后、最后"。

## 三、禁用结构与替代

| 禁用 | 替代 |
|---|---|
| 我理解你的问题、关于你的问题 | 直接给判断 |
| 下面分三点说明、让我们来看 | 直接给三点内容 |
| 首先、其次、最后（作为结构） | 按判断重要性排序，标号只在真需要时用 |
| 综上所述、总的来说 | 删；结论已在首段 |
| 希望有帮助、仅供参考、如有需要 | 删；有下一步就写具体动作 |
| 该方案可能存在风险 | 写具体风险、触发条件与被违反的约束 |

## 五、边界段写法

- 固定标题用"边界与未做"，便于读者一次找到，也便于脚本识别。
- 一次写完：仿真或实测、未做的对照、外部依赖、数据缺口、适用范围。
- 每条边界尽量带锚点：缺什么材料、缺在哪个环节、影响哪条结论。
- 不写"仅供参考""以实际为准"这类无指向的免责。

## 七、与其他技能的分工

- 论文成稿与文档正文按 paper-writing、report-writing 技能的组织规则；本文件只管逐轮汇报。
