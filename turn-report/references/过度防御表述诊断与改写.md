# 过度防御表述诊断与改写

本文件是 T5 与 D1—D8 的判据正文：什么算过度防御、什么只是必要的不确定性、怎么分级、怎么改。汇报结构见[结论优先汇报结构](结论优先汇报结构.md)，缩写单列[缩写与术语首现规范](缩写与术语首现规范.md)。三份文件各管一段，不重复立规。

## 一、问题定位

过度防御不是"话说多了"，是结论、证据、边界三件东西放错了位置：

- **结论缺位**：读者读完不知道作者判断什么。
- **证据稀释**：判断被过程叙述、背景和限定语包住，找不到可核查对象。
- **边界弥散**：同一句不确定性反复出现，读者无法区分"真不确定"与"礼貌保险"。

这三件事合起来，读者要重做一次推理才能得到结论——而推理所需的证据往往已经不在文中。

## 二、八类病灶（D1—D8）

| 编号 | 病灶 | 判据（可数） | 改法 |
|---|---|---|---|
| D1 | 结论缺位或后置 | 首段 200 字内无判断句；或先讲背景、过程，最后才给决定 | 首段不超过五行，先写"做了什么、结论、能不能用" |
| D2 | 免责循环 | 同一不确定性在 ≥2 处出现，且不在统一的边界段 | 合并进"边界与未做"一段，全文只留一次 |
| D3 | 强度失配（双向） | 已跑却写"似乎、可能、大致"；仅推断却写"已验证、已复现" | 按第三节五档映射 |
| D4 | 空洞抽象 | 赋能、抓手、闭环、鲁棒性、协同能力、体系化、全链路等无实指名词 | 换成"改了哪行、数字多少、失败几次" |
| D5 | 模板残留 | 我理解你的问题、首先我们、综上所述、总的来说、希望有帮助、仅供参考 | 删除，直接给判断 |
| D6 | 复述与冗余 | 重复背景、逐条复述过程、把用户已知的再讲一遍 | 按判断组织，不按流程复述 |
| D7 | 回避判断 | "建议进一步核实"顶替"我判断 X，依据 Y，推翻条件 Z" | 判断加锚点加可证伪条件 |
| D8 | 缩写裸用 | 形如 MILP、VTW、GSD 的大写串首现无中文名或英文全称 | 首现写"中文名（English Full Name, ABBR）"；全称未知标待核 |

## 三、校准五档

过防御与过自信是同一个错的两端：措辞强度不等于证据强度。只治一端会制造另一端。

| 证据状态 | 允许措辞 | 禁止措辞 |
|---|---|---|
| 实跑并有独立回放、复核或最优证书 | 直述"是、为、已交付、最优（限该候选集）" | "可能、似乎"——降格也是失实 |
| 跑通但未独立复核 | "跑通，未独立复核" | "已验证、已复现、最优" |
| 只读代码或公开资料 | "读代码（路径与行号），未运行"、"读公开资料，未实测" | "实测、复现" |
| 仅设计或推断 | "推断、设计层、按设计应" | 任何完成时态 |
| 明确未做 | "未做、未运行、未取得"（必须写出来） | "可能存在差异"——软化等于隐瞒 |

## 四、归因：为什么会写成这样

| 成因 | 机制 | 干预 |
|---|---|---|
| 模型偏好 | 选择普适、低风险、覆盖面最广的表述，信息量最低 | T2 强制锚点，T6 篇幅守恒 |
| 验收焦虑 | 无法验证就加保险，越不确定限定越多 | T4 五档映射，把"未验证"压成一句定性 |
| 文风传染 | 项目里的验收报告本身是密集体，后续 Agent 模仿其语气与缩写习惯 | 项目入口给正面样例 |
| 契约缺项 | 没有规定汇报结构与术语首现，模型回落到默认模板 | T1、T3、T5、T7 给结构与禁用集 |
| 篇幅激励 | 长文显得认真，缩写显得专业 | T6 以判断条数为分母；T7 禁止拿缩写当行话 |

## 五、分级与处置

分级看改动风险，不看特征强度。

| 级 | 含义 | 处置 |
|---|---|---|
| A 机械改 | 删套话、导览、结尾软化、空泛词，补缩写全称；不触碰语义 | 直接改 |
| B 建议改 | 结论后置、免责分散、强度失配、缩写与术语不统一 | 重组结构，保留原判断 |
| C 只报告 | 整篇篇幅或结构与任务类型不匹配 | 给建议，不逐句改 |
| P 必保留 | 限定条件、单位、版本、失败与负结果、未做声明、引文、代码、数值区间 | 不得当病灶删除 |

## 七、P 级：必须保留的内容

改写时逐项过一遍，缺一项就是信息丢失：

- 限定条件与适用域（"在 45° 离轴、405 Mbps 下"）；
- 单位、量纲、坐标系、时间系统；
- 版本、提交号、配置标识；
- 失败、负结果、回滚、跳过；
- 未做、未运行、未取得、外部依赖；
- 引文、代码、字段名、数值区间与不确定度。

## 八、误伤与反例

以下不是病灶，不得按 D1—D8 处理：

- 有依据的单次"可能"：证据确实只支持可能性时，写"可能"是准确，不是防御；
- 边界段内的限定语：集中交代时允许密集出现；
- 方法名里的缩写：已按 T7 首现定义后，后续使用是正确用法；
- 表格、代码块、公式、引文：不进入改写范围；
- 项目或期刊要求的固定声明：保留原文，位置可调到边界段。

反例（改坏了）：

- 为压缩篇幅删掉"未运行"，把只读代码写成"验证通过"——违反强度校准；
- 为"像人写的"打散句子、加口语、造错别字——违反信息守恒，且本技能不以此为目标；
- 把"在 45° 下"改成"一般情况下"——把条件结论改成普遍结论，属失实。

## 九、复测口径

1. 改后重跑 `reply_lint.py`，警告项应清零，或有逐条保留理由。
2. 逐条核对 P 级清单，确认没有为清零而删信息。
3. 同一免责在全文只应出现在边界段一次；出现两次即回退检查。
4. 缩写首现应全部有定义或标待核；定义格式不统一按 B 级处理。
