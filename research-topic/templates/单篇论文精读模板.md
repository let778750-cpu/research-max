# 单篇论文精读模板

依据[精读规范P1—P9](../references/论文精读与证据核验规范.md)填写。本文件是空白工作模板，不表示任何论文已经精读或复现。

复制下方两个注释标记之间的内容到自己的笔记目录。将`【填写：……】`替换为实际内容，保留必要来源；未知、未找到、无法取得、未报告和不适用按P3区分。全文使用连续解释，表格承担必要索引，不必把每个提示都扩写成相同长度。

- **筛选阅读**：先填第1、2、13节，其他节标“本轮未展开”。只依据实际可见材料填写；“全文主线”、机制和理解检查中尚无依据的字段标未读／待核，不强行填满，不得宣称完成深读。
- **详细精读**：核心节为第1—4、8、10、12、13节，必须填写或写明不适用原因；扩展节为第5—7、9、11节（标“扩展”），按阅读目的展开，未展开时标“本轮未展开”。填写十三个主题中适用内容。按P5将实验替换为证明、材料分析或证据综合；不适用项说明原因。
- **代码拆解或复现**：按实际目标扩展第9节。不能把未执行的命令或预期输出写成运行结果。
- **避免重复**：S01只完整展示一次，其他节引用其相应步骤；主张、实验、图表可按需要编C、X、F等短编号。项目已有主张总表或样本链路时直接链接对应项。
- **写作训练**：第11节用于全文论证拆解；只有要练习具体句式时，才另用 paper-writing 技能的范文学习卡。

配置项是当前研究问题、读者知识、阅读目的、论文类型、资料目录及可用资源；不固定研究领域、Benchmark、模型厂商、文章数量和字数。原图按[阅读笔记原图规则](../references/论文精读与证据核验规范.md#reading-figures)放在解释它的位置。

# 【填写：论文短标题】精读笔记

## 1. 论文身份与阅读导航

| 项目 | 填写内容 |
|---|---|
| 题名与作者 | 【填写：正式完整题名、中文释义、作者；机构仅作背景信息】 |
| 发表信息 | 【填写：年份、刊会/平台、文章类型、发表状态及核查入口】 |
| 唯一标识与版本 | 【填写：DOI/arXiv版本等；预印本、正式版及勘误关系】 |
| 本地原件 | 【填写：PDF/原始材料、Markdown和补充材料位置；关键原件SHA256】 |
| 获取与转换记录 | 【填写：引用已有文献目录或记录；未有记录时填获取缺口、实际转换器与版本、已知缺损及检查范围；不要复制一套状态账】 |
| 代码、数据与项目页 | 【填写：准确入口及许可核查情况；没有找到时写已查范围】 |
| 对应实现版本 | 【填写：commit/tag、数据release、环境文件；与论文的对应是否已确认】 |
| 本次阅读目的 | 【填写：当前研究问题、希望解决的疑惑或要作出的决定】 |
| 阅读者与日期 | 【填写：记录者、本轮日期、AI辅助范围和实际人工核查情况】 |
| 实际读取范围 | 【填写：正文、附录、图表、代码文件；明确未读部分】 |
| 核验与执行范围 | 【填写：仅阅读/对照原件/手算/静态代码追踪/实际运行的具体对象；分别记录】 |
| 笔记状态 | 【填写：沿用项目状态；未核实项及本轮完成范围，勿预置“已完成”】 |

**全文主线**。【填写：用一段话连接现实或理论问题、作者关键想法、证据取得方式、主要发现及边界。不要只逐句翻译摘要。】

**阅读导航**。【填写：最有助于理解的图、表、章节或定理，以及各自回答什么问题。】

| 必要术语/缩写 | 通俗解释 | 在本文中的作用 | 需要补充的背景或来源 |
|---|---|---|---|
| 【填写：关键术语】 | 【填写：避免用另一个术语代替解释】 | 【填写：它影响哪个步骤或判断】 | 【填写：具体来源；已掌握时可省略补读】 |

## 2. 背景与科学问题

**2.1 背景与已有做法**。【填写：谁或什么对象面临什么问题，已有研究怎样处理，具体在哪些条件下不足；说明必要领域知识和最近邻工作。区分作者的相关工作叙述与本轮补查。】

| 层次 | 本文的问题 | 原文依据与证据角色 |
|---|---|---|
| 现实需求或理论动机 | 【填写：为什么值得研究；纯理论论文可用知识缺口】 | 【填写：页/节或外部一手来源】 |
| 待解释/测量的现象 | 【填写：概念、可观测量及两者关系；非测量研究说明对应对象】 | 【填写：作者定义或我们的概括】 |
| 可检验问题/待证命题 | 【填写：能被什么观察、比较、证明或反例支持/否定】 | 【填写：原文问题；未明说时标分析推断】 |

**2.2 贡献定位**。【填写：已有工作已经解决什么；本文新增的是问题、数据、机制、理论、系统、评价还是新证据；为什么这个差异有意义。最近邻尚未核实则保留边界。】

**2.3 问题边界**。【填写：目标人群/系统、条件、时间、领域、任务及未覆盖范围；区分描述、预测、机制解释与因果主张。】

## 3. 研究对象、任务定义与完整例子

| 约定 | 本文的具体定义 |
|---|---|
| 研究/评测对象与单位 | 【填写：模型、完整系统、群体、材料、数学对象等；一个样本/单位是什么】 |
| 输入或可用材料 | 【填写：内容、格式、测量条件；理论研究填前提和定义】 |
| 允许信息与操作 | 【填写：资料、工具、反馈、干预或分析权限；不适用则解释】 |
| 输出或待得结论 | 【填写：答案、文件、估计量、主题、定理等及其形式】 |
| 成功或可信判断 | 【填写：正确性、约束、证明有效性或解释依据，不混淆不同目标】 |
| 资源和适用限制 | 【填写：时间、次数、设备、信息范围、假设等】 |
| 子任务差异 | 【填写：各类任务的定义与判据变化；单一任务则说明】 |

**贯穿实例S01**。【填写：原文样本ID、页/图/材料位置和选择理由；理论可用最小数学实例，定性可用材料到主题的片段。自拟时明确写“教学示例”。】

1. **原始问题/材料**：【填写：理解该例所需的实际输入；注明省略内容和来源。】
2. **条件解释**：【填写：哪些是已知、假设、未知、干扰及允许使用的信息。】
3. **期望产物**：【填写：具体输出形式或待证命题；参考答案/真值/解释来自哪里。】
4. **处理路径**：【填写：一步步怎样处理到结果，保留影响理解的中间状态；详细方法引用第4、6节。】
5. **判断过程**：【填写：输出如何被解析、评分或论证，得到怎样的判定；数字是原文还是教学值。】
6. **失败/边界例**：【填写：一个看似合理但会失败的输出，或改变哪项条件后论证不再成立；注明原文或自拟。】

**从个案到整体**。【填写：这个例子说明什么机制、没有证明什么普遍能力；无法追踪的环节明确列出。】

## 4. 核心方法与整体流程

**4.1 关键直觉**。【填写：方法抓住了哪个困难，为何可能有效；让有必要背景的读者先理解想法。】

**4.2 输入到输出**。【填写：按实际顺序解释流程，必要时画简图。区分数据构建、方法执行与评分/分析，不把并行过程画成串行。】

| 步骤/模块 | 输入与输出 | 实际操作 | 设计理由与假设 | 作者新增/沿用 | 证据位置 |
|---|---|---|---|---|---|
| 【填写：步骤】 | 【填写：关键字段/对象变化】 | 【填写：具体怎样做】 | 【填写：解决什么及为何这样选】 | 【填写：来源与增量】 | 【填写：页/式/代码】 |

**4.3 关键衔接**。【填写：S01在哪一步发生决定性变化；反馈、迭代、停止、异常和回退怎样处理。原文缺失的衔接不能凭常识补成事实。】

**4.4 可替代的设计**。【填写：为什么不用更简单方法；作者是否比较过；我们的替代想法属于待验证建议。理论研究解释关键证明技巧为何需要。】

在此嵌入并解释对应方法/流程原图；同图后文再用时链接此处。【填写：原图号、版本、位置、读图方法，以及它和文字步骤如何对应；无相关图则说明。】

## 8. 结果、核心图表与结论边界

### 核心证据【填写：图/表/命题编号；按需复制】

在首次分析该发现处插入原图或准确整理的表格。【填写：来源版本与位置、图注必要信息；整理/重绘时明确标识。方法和数据图留在其对应章节，不集中移来。】

1. **怎样读**：【填写：行列/坐标/单位/图例/误差条/子图含义，及比较条件。】
2. **看到了什么**：【填写：关键数量、差异和分母，或定理/主题的准确结论；区分作者报告和本轮复算。】
3. **支持什么**：【填写：对应第7节哪项问题，在何种条件下支持哪条主张。】
