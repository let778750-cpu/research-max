# 新研究项目入口

这是空白项目骨架，不含已完成的科学工作。先填写`project.json`中的名称、范围与当前阶段，再根据实际研究拆分`tasks.json`。十个G任务是阶段占位，其空验收条件必须在开工前补齐。

## 建议目录

初始化工具建立如下目录；手动复制时可按需创建，不必为不适用的阶段堆文件。

| 路径 | 用途 |
|---|---|
| `protocol/` | 问题合同、方案、冻结决定及变更 |
| `literature/` | 原文索引、阅读卡和引用核验 |
| `data/` | 原始来源、划分与加工谱系；敏感原件按许可另存 |
| `src/` | 实现、评分与分析脚本 |
| `runs/` | 独立运行目录、原始输出、失败与费用 |
| `artifacts/` | 任务产物、审计和主张证据表 |
| `reviews/` | 绑定具体版本的复核记录 |
| `manuscript/` | 权威稿、图表源及投稿导出 |
| `snapshots/` | 工具生成的指定文件内容快照 |
| `submission/` | 真实投稿与修回材料、回执 |

`tasks.json`是唯一任务状态源。`project.json`记录项目范围和当前阶段；`submission_profile.json`保存从真实模板提取的要求及原文定位，未知值保持null。不得从其他项目复制ACCEPTED、预算授权、作者身份或正式冻结状态。

开始时先完成G0问题卡和最近邻分析；已有方案可直接分解任务，但仍须核对数据、原理及评分的前置证据。没有确认性测试的研究，可在`project.json.decisions`记录理由后调整任务依赖与快照前置任务，明确探索性范围。

独立复核记录格式与实验协议见本技能 references/；写作与投稿要求见 paper-writing 技能。此README不记录实时完成清单，避免与任务账本出现两份状态。
