# GitHub 记录接入（空白模板）

只在用户指定任务采用 GitHub 记录并开始执行后填写；不要原样复制待填值作为授权。保持已有计划、任务、ID和证据，不重建历史。分组判断见[方案落地与任务关卡](../references/方案落地与任务关卡.md#模块粒度与外部执行)，执行规则见[GitHub模块记录](../references/GitHub模块记录.md)。

## 给当前主持者的接入要求

- 权威项目与任务文件：待填写
- 指定 GitHub 仓库：待填写；新建或接入已有：待填写
- 用户指定的任务范围及授权来源：待填写
- 当前运行、占用及未提交修改：待核对
- 首批明确发布的文件：待填写

先读取现有计划、任务、实际进度、验收及运行占用；说明记录与产物的实际差异，再在指定范围内接入。总览和PR复用现有审核，通过后自动合并并汇报。下面两节复制到权威任务文件的任务卡之外，填写后仅保留一份当前约定，不在模块中另填状态。

## GitHub记录约定

- 仓库：待填写
- 指定任务：待填写
- 授权来源：待填写
- 当前接手者：待填写
- 发布：待填写
- 合并方式：待填写
- 基线分支：待填写

## 模块分组

| 模块 | 任务 | 共同产出 | 集成条件 |
|---|---|---|---|

仓库填owner/repo；指定任务列明确ID；发布填允许、暂停或结束；本模式合并方式填自动。模块ID使用M-前缀；成员以顿号或逗号分隔；集成条件写实际检查，已有任务验收覆盖时说明如何覆盖。未启用项目无需这些内容。
