# 唯一研究反馈循环

本文件维护从问题回到证据、再形成修订的完整协议，其他文件引用本流程。

## 探索中的短循环

探索的目标是减少影响判断的未知，不要求每次都提高指标或形成论文贡献。每个有意义的批次回答：现在不懂什么、事前预计什么、本次检查能区分哪些解释、实际观察到了什么、判断如何改变。对照与资源限制尚不清楚时，先把它们作为待查问题。

下面的循环同时适用于观察、复现、反例检查和方法改动；按任务选择必要步骤，不为每次工具调用填一张表。使用[实验协议中的可选探索记录](../templates/实验协议与冻结单.md#探索记录按需填写)链接原始结果，简化与扩大验证遵循[实验层次](实验运行与复现.md#从最小检查走向目标条件)。

1. **登记问题与现象。**执行前记录待查问题和预期观察；没有合理预测时写未知，不能看过结果后补成事前预测。保存实际样例、日志与版本，注明训练、开发、测试身份；比较预期与实测，先记录现象，不提前认定原因。
2. **定位层级。**区分数据或标签、领域假设、代码、评分、不可辨识、资料不适用、决策未落地及资源问题。局部失败先判断否定的是实现、机制、测量方式还是研究问题；证据不足时先区分原因，不自动缩小整个方向。资源暂缺与科学价值不足分别处理。
3. **回查原文。**先查已有来源与阅读卡，再补检索一手资料；记录支持和反证。新增参考资料不自动进入被测知识库。
4. **提出最小检查或改动。**选择在可用资源内最能区分解释的一项行动；可以只是观察、复算或构造反例。改方法时明确改哪一处、预期影响哪项观测或指标、可能损害哪些样本、成本和否定条件。多个因素尽量分开验证，必要交互明确作为联合假设。
5. **在开发区验证。**保留旧版本和全部尝试。生成经验与验收经验的组分开；开发验收反复使用也会适应，记录次数并用预算或预设规则限制。
6. **复核与回归。**使用新反例和固定回归例，必要时独立实现。检查收益是否来自泄漏、额外信息或计算资源、弱化对照、随机波动、删除失败或改变分母；按比较目的控制差异，不能把额外投入的收益归因于新机制。
7. **更新判断与取舍。**采纳项发布新版本；拒绝项进入失败史，不进入有效经验。无法区分的原因保留为假设；新发现也可促使扩大或重构问题，按下表判断调整层级。
8. **同步下游。**更新问题与决策账、受影响任务、知识版本、分析和稿件。全局记忆只存结论与链接。

## 调整方向与结束探索

“重新选题”应先分清改变的层级，由证据决定是否调整及调整哪一层：

| 调整层级 | 触发依据 | 需要更新什么 |
|---|---|---|
| 下一项检查或实验 | 当前结果留下了更关键、可区分的未知 | 下一项行动及预期观察 |
| 机制假设或方法 | 反例推翻原解释、简单方法已解释同一现象，或新观察提示另一机制 | 假设、竞争解释和相关对照 |
| 研究问题 | 新异常、新联系或更有价值的问题改变了原目标；或目标不可观测、核心缺口已被解决、所需证据与资源不可得 | 比较保留、扩大、重构或放弃的理由；更新问题卡、最近邻、可行性和受影响任务，范围决定按既有授权处理 |

选择下一步时说明依据，而非只给“继续优化”：

| 决定 | 适用条件 |
|---|---|
| 继续或扩大验证 | 现有证据足以支持进一步投入，且扩大验证能回答尚未解决的问题；不是仅因分数上涨 |
| 补判别证据 | 多个解释仍与结果相容，优先找能区分它们的检查，不连续堆加组件 |
| 调整研究问题或主张 | 新发现支持扩大、合并或重构问题；关键假设受反证、目标条件不成立时，调整相应层级；贡献只在局部成立时缩小主张 |
| 暂缓或停止 | 前置证据暂不可得、已达约定预算或停止条件，或在可用资源内没有足以改变判断的下一项检查；区分资源不足与科学否定 |
| 接受负结果或保留简单方法 | 充分比较未支持新增机制，或简单基线已经满足目标；保留适用边界和失败记录，不强迫增加AI或复杂度 |

这些是研究判断，不新增任务状态。候选比较与聚焦依据见 research-topic 技能的问题与创新论证一文。结果如何进入正式主张，仍由原有证据、统计和冻结要求决定；正式测试后发生调整，按下表处理。

## 计划调整后同步任务

尚在比较的建议保留在待判别问题中；已采用的调整写入当前计划正文。既有授权内的实施细化持续推进，研究目标、预算或外部动作确需决定时沿用协作规则，不把修订号变成审批关卡。

1. **确定改变了什么。**区分步骤细化、输入/方法调整和交付目标变化。实质调整在总体计划记录一个变更编号、采用理由、影响范围及可复用成果；正文始终能直接说明当前生效方案，不让接手者靠叠加历史修订重建现状。
2. **定位影响范围。**沿任务依赖查找候选下游，再检查它是否实际消费变动的输入、接口或假设。共享评分、数据划分、单位、资源及验收标准另作横向核对，依赖图未登记不表示没有影响。给受影响成果判断“仍适用、补核验、返工”，保留依据；不因计划整体修订而默认全体重做。
3. **局部调整任务。**按[任务身份与承接](方案落地与任务关卡.md#任务身份与承接)保留ID或拆分替换，修改必要依赖、要求和下一步。明确旧证据适用范围；新要求下不能继续使用的旧回执移入变更记录引用，当前验收另行绑定。不影响的已授权工作继续；仍在运行的旧任务核对输入版本和写域，其回执只按派发时的要求认领，不能自动签收修订后的任务。
4. **核对并结束同步。**总体计划维护生效修订号，任务文件仅在影响处理和目标覆盖核对完成后更新“已同步计划修订”。检查新增目标有任务承接、退出项不再误入工作队列、依赖无环、阶段出口及快照前置任务仍指向有效交付、旧验收边界明确、下一步可执行；任务ID或范围变化时同时核对项目配置中的 snapshot_required_tasks；再刷新已有派生概览。只改编号不算同步。多人协作由共享文件的指定维护者顺序更新，途中接手时先处理不一致，受影响工作不依赖混合版本继续。

修订号用于识别两份文件的同步情况；同一文件内的计划与任务无需双写同步标记。任务要求版本只约束该任务的目标、关键输入、依赖、复核方式和验收条件；普通进度、人员接替、实施步骤细化不改变这些要求时不触发重验。具体可选工具写法见[Markdown任务格式](Markdown任务格式.md#计划修订与验收依据)。没有工具时仍按上述证据判断处理。

## 正式测试后的变更分流

| 变化 | 处理 |
|---|---|
| 明确实现错误 | 封存旧版，说明影响，按原协议重跑全部受影响单元并披露；必要时降低确认性解释 |
| 方法、提示、阈值、样本规则或知识变化 | 原测试已成为开发信息，新方法需要未曝光测试，或明确为探索性结果 |
| 仅解释与文献补充 | 可以更新写作，不回写为正式运行时已使用的资料 |
| 图表排版或措辞 | 保留分析数据，重建受影响图稿并检查一致性 |
| 来源补证 | 建新证据与当前视图，保留旧失败记录；不可抹掉历史未核实状态 |

不得反复冻结同一曝光测试并宣称重新盲测。因预算不足缩减规模时，按预定优先级调整重复或次要扩展，不能根据效果删不利样本或主对照。

## 避免维护操作污染证据

复跑前检查脚本是否原地重写日志、时间戳或已冻结结果。验证输出写到独立运行目录，确定性内容与本次运行元数据分开；同一个科学输出不应因记录时间变化被覆盖。内容未变但元数据变动也须说明，不能静默重算清单后声称从未改变。

任务与冻结清单只能有一个写入者。并发补证使用独立作用域和自己的清单，不在别人运行时全树重封。版本身份应绑定代码、配置、输入和有影响的资料，恢复运行沿用相同身份。

## 变更涉及外部执行时

仅对已由用户指定采用外部执行的任务，额外核对正在运行的尝试、输入与要求版本。旧尝试不能直接验收新要求；无关计划修订允许保留有效证据。等价实施拆分记录承接并更新明确执行范围，新增研究目标不自动继承授权。暂停、接管与修回见[跨Harness任务执行](跨Harness任务执行.md)，不将此流程推广为所有任务的固定审批步骤。
