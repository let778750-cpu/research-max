# 数据、标签与知识的准入

## 复用优先，但重新确认用途

先查已有数据、代码、原始结果与许可，再决定下载或重新生成。保存原件只读入口，用清单引用大数据，避免每个模型复制一套。获取时记录来源、版本、范围、日期、大小和哈希；下载先临时文件后核验，HTML错误页不能当成数据文件。重试有限，续传核对服务端版本。

原件、清洗与派生结果分开。派生产物关联输入、代码、配置和随机种子；真实测量、产品重建、预测产品、人工噪声和仿真状态保留类型标记。未知精度不能写成已知协方差，产品统计离散度也不自动是测量噪声。

## 七项准入

| 检查 | 需要回答 |
|---|---|
| 来源与权限 | 来自哪里，允许本用途和再分发吗 |
| 文件完整性 | 可解析、字段和覆盖符合来源说明吗 |
| 物理或测量语义 | 单位、参考系、时间、仪器、误差与采样如何定义 |
| 标签与构念 | 谁标注、依赖何证据、时空容差、阴性是否完整 |
| 派生与不确定性 | 清洗、插值、排除和噪声依据可追溯吗 |
| 任务适配 | 现有字段真的支持拟使用的方法和目标吗 |
| 分组与隔离 | 同源、近重复及测试信息是否跨边界泄漏 |

状态可用`SOURCE_CONFIRMED → UNDER_REVIEW → ADMITTED或EXCLUDED`。官方来源只解决来源问题，哈希只解决完整性的一部分。排除给出原因与数量；困难样本、失败产品不能因成绩不好而消失。

清洗检查非有限值、重复、时间非单调、缺段、量纲、坐标和误差字段。先标记问题，再决定剔除、保留或插值；不要把真实事件平滑掉。仪器实验另记录校准、批次、试剂或样品、操作者、盲法与必要审批；这些领域要求由项目合同启用。

## 先分组，再划分

按患者、对象、任务家族、母轨迹、生成条件或批次定义独立单位。同一原件的裁剪、增强、噪声变体与近重复跟随同组；时间任务还核对未来信息。正式集曝光史永久记录，换名字、换目录或重新冻结不能恢复盲性。

检查输入特征、文件名、ID、顺序、缺失模式、元数据、控制器指纹和缓存是否透露答案。可见字段采用白名单；真值只进入评测侧。只分文件夹不是访问隔离，要核验实际进程、工具入口、序列化字段和检索范围。

## 受控生成

先定义目标或干预，再生成过程、成败与观测，避免按结果倒推标签。记录生成器与检测器的假设关系，安排失配、联合异常与困难反例。更换积分器仅验证数值敏感性，未必构成物理模型失配。合成与真实外部验证分开计分。

## 知识与经验

原文→带来源及适用条件的证据块→质检→可用知识版本。原文中的限制、反证随片段保留；条件未知应显式处理。库规模不等于检索有效性，用相关、无关、冲突和不适用资料的开发样例检查。

静态知识、经验候选、已验收经验分开。经验必须有适用范围、生成组、独立开发验收组、反例、回归及撤销条件；不存样本答案。正式测试期间冻结有效知识与提示。研究记忆库、审计报告和测试失败分析不能自动进入被测系统检索区。

交付使用[数据与划分卡](../templates/数据与划分卡.md)，至少保留数据准入、分组与曝光史，不以“已下载”代替准入。
