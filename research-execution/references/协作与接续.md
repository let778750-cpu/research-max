# 人与AI协作、复核及交接

## 先界定两种系统

研究执行团队负责资料、实现、运行、分析和写作；论文被测系统是实验对象。前者使用多代理不意味着后者是多智能体。分别记录各自模型、工具、权限与费用，不把执行团队能力写成方法贡献。

模型计划名称、接口别名、实际返回身份和不可观测属性分开。无法核实的型号、思考档或图像模型如实记未知，不用配置字符串证明运行身份。采用高推理档或知名模型不替代科学复核。

## 理解、质疑与判断分工

人负责研究价值、关键取舍和证据解释，AI负责提供可核查的备选、实现和分析，并可指出研究者判断中的问题。对尚不理解的关键结论，先补解释或检查，不因AI回答流畅、模型知名或多次重复就认定成立。AI自评和多个模型的意见可用于发现问题，不能认证科学正确、新颖性、复核独立性或录用概率。

开放讨论与聚焦依据按 research-topic 技能的问题与创新论证一文执行。AI可以直接推荐下一项行动或拟推进问题，但用户继续追问不等于接受先前题目。只有容易混淆时才简短说明建议属于局部检查、探索问题还是论文主张，不给每轮回答加固定声明。

围绕影响当前判断的疑点，按需使用四类追问，不要求每轮机械问完：

| 追问 | 有用的回答应包含 |
|---|---|
| 依据在哪里？ | 原文位置、数据、计算或运行记录；明确哪些是观察、哪些是推断、哪些仍是假设 |
| 为什么优先检查这一点？ | 它影响哪项决定，与替代行动相比能减少什么未知及需要什么资源 |
| 还有什么解释？ | 能产生同样现象的竞争解释，及当前证据尚不能排除的部分 |
| 怎样用最小代价区分它们？ | 一项可执行检查、不同解释的预期差异和可能仍无法判断的结果 |

解释从通俗直觉和具体例子进入，再按需要连接公式、实现和适用边界。一句话可以帮助进入问题，不能代替证明或略去决定结论的条件。用复述、重建一个例子或提出反例检查理解，具体方法复用 research-topic 技能的精读规范，不另设一套理解评分。

在既有范围、权限和预算内，AI持续执行已明确的检查与实现；这些追问是协作方法，不是逐步审批。涉及研究方向或资源边界的决定，先按[证据反馈](证据反馈与变更控制.md#调整方向与结束探索)形成具体选项，再按下文的日常沟通规则处理。

## 并行条件

在用户与宿主允许委派时，独立资料核查、互不重叠的实现和非作者复核可并行。写同一文件、依赖尚未稳定的修改或共享状态更新顺序执行。没有并发需要时单人完成即可，不把代理数量作为质量指标。

任务书写明输入版本、依赖、唯一写入范围、预期产物和验收；工作者不自行扩大范围或递归委派。收到产物后核对任务绑定、路径、哈希与内容。编写者自检与非作者复核分开，复核者不能只照抄作者的预期结论，应查看原始输入和反例。

## 任务正文投递失败时的可选兜底

只有宿主确实无法可靠传递正文时才启用文件邮箱：准备不可变任务正文和唯一TOKEN→取得邮箱槽位→子执行者ACK其任务及正文哈希→协调者确认后释放投递槽→执行→回执返回TOKEN、产物及哈希→协调者核验。

单槽仅串行化**投递与确认**，已确认且写入范围独立的工作仍可并行。未确认前不能抢占，也不能覆盖其他项目邮箱；过期任务归档不删除。该方式不是操作系统沙箱，也不是多代理服务。本库没有自动创建全局邮箱或启动代理。

## 接续必须交代

先从项目入口确认权威总体计划和任务文件，再读当前模块的任务卡、必要上游证据与对应复核；旧聊天只提供线索。短任务可在同一 Markdown 接续，无须重新生成一整套文件。当前状态、剩余工作和下一步以任务卡为准，交接摘要只链接并补充跨任务授权、资源或运行状态，不复制实时状态表。

计划刚调整时先核对生效修订与任务同步情况，接着读相关变更及原验收边界；任务回执对应旧要求时按旧范围接收，按[计划同步流程](证据反馈与变更控制.md#计划调整后同步任务)处理受影响工作。

多个执行者各自在获准范围交付产物，由指定负责人维护共享任务文件；更新前重读相关任务区，保留他人变更。单写者约定降低冲突，不等于文件系统事务或沙箱；工具遇到源变化时重新核查，不把派生汇总反写成权威状态。


当前目标与范围；权威文件；已验证发现和未验证假设；实际完成与未完成；阻塞及其证据；费用余额或未知状态；下一项可执行任务及输入；刚改动的上游与需重审的下游。旧聊天只作线索，原始数据、状态和复核文件仍是入口。

交接者说明README是否与状态账一致，历史快照是否只覆盖一部分文件。接手者先做只读核验，不能用一次新封存抹掉差异。见[交接与修回模板](../templates/交接与修回模板.md)。

### 上下文与成本

先按当前问题读目录、阅读记录和证据索引，再加载必要章节、代码或日志。核心论文保持论证连续性，重要新判断回到原文；文献获取、转换与精读细则按 research-topic 的 D1—D8、P1—P9 执行。来源版本未变且派生产物可用时复用下载、转换和笔记；版本变化只重查受影响部分，不重做整条流程。

互不依赖的元数据核查与文件检查可成批执行，返回结构化摘要和证据定位。控制单批规模，避免把整库全文、巨大日志和重复结果读入上下文。在自然检查点复用现有任务或阅读记录，留下当前问题、已读范围、关键证据位置、未决缺口和下一步；不逐次工具调用填表，也不为接续另建重复报告。

在已授权范围内连续完成常规获取、分类、转换与核验；缺全文、范围取舍或资源边界确实影响后续工作时及时请求用户介入，同时推进独立部分。问题理解、竞争解释和研究取舍保留必要讨论，不以减少对话轮次为质量或费用目标。

实际 token、耗时和费用可得时按现有记录登记，不可得则标未知。文件读取量、重复处理次数与用户补充次数只能作辅助指标，不能换算或冒充真实费用；未经真实比较不宣称成本或科研效果改善百分比。

## 日常沟通

在授权范围内持续推进可逆工作。重大研究范围、预算上限或外部提交确需决定时，先完成不依赖该决定的准备，呈现具体可审阅选项，并说明询问的依据。反馈允许反驳研究者，但必须指出证据、竞争解释和可验证路径，避免仅用“可能有风险”阻停工作。

## 分歧与例外处理

先确认分歧属于事实、科学解释、审美偏好还是权限问题，四类处理方式不同。可逆且已授权的实现选择直接做出可审阅版本；只有确实缺失且影响结果的信息才停下来询问。不把技能或模板的建议自行升级为审批门槛。

模板要求与用户偏好相冲突时，标明出处和具体影响，准备可比较的版本；不能声称一份不符合模板的稿件"严格合规"。模型不可用、字体无法认证、原图分辨率不足这类能力限制，一律记录实际状态，不凭提示词或配置字符串认定达标——"如实记录"与"换成替代方案"是两件事，都要做但不可互相冒充。

## 项目配置域

跨项目会变、必须由当前项目决定的十个配置域（通用判据见下表；空白模板 `submission_profile.json` 随[项目骨架](../templates/项目骨架/README.md)分发，逐项记录取值、来源与核验状态）：

| 配置域 | 需要决定什么 |
|---|---|
| 研究对象与外推范围 | 由科学问题与数据划分确定，不预设场景数量 |
| 模型与执行团队 | 分别记录计划、可用能力与实际身份；不指定提供方 |
| 费用与重复次数 | 小试后确定，并记录已有开销 |
| 引用数量与字数 | 读目标刊会与文章类型要求，不预设数值 |
| 字体、单双栏、图尺寸 | 实际模板优先，记录来源及日期 |
| 图件载体 | 按任务与投稿要求选择；排除生成式造假是通用要求，载体不是 |
| PDF 生成链 | 最终提交源必须一致（DOCX 投稿从最终 DOCX 导出，TeX 投稿从最终 TeX 编译） |
| 引文位置 | 按目标模板核对正文与文末 |
| 中西文间距 | 按语言及版式合同设置 |
| 图中文字 | 精炼、含义明确，不用模糊压缩标签 |

未知填 `null` 或"待核实"，不用任何来源项目的旧值补空；数值 0 只能表示真实的零。用户当前明确选择可覆盖本技能建议，但不能让虚构事实成为真。

## 用户选定的外部执行者

用户指定具体任务使用外部Harness时，按[跨Harness任务执行](跨Harness任务执行.md)准备、派发、审核和接续。单一状态源与实际授权仍适用；历史执行约定不自动启动新窗口。只使用本技能进行讨论或普通执行时，无须填写外部执行字段。
