# 全流程的输入、产出与关卡

## 先建立事实入口

接手时核对：当前用户目标与授权、研究方案、任务状态、数据与分析入口、原始投稿要求、有效版本清单。README用于导航，任务账本记录状态，产物与复核记录证明完成；三者冲突时登记差异，回到原始证据，不能静默择取最有利的一份。

历史材料可复用，但要重新检查来源、版本、标签、训练覆盖、许可和用途。保留历史验收记录，新的任务不自动继承其通过状态。研究记忆库记录结论及工件链接，不作为数据或被测系统知识的替身。

## 阶段表

| 阶段 | 核心问题 | 最小退出证据 | 未通过时 |
|---|---|---|---|
| G0 问题与可行性 | 领域需要解决什么，已有方法缺在哪里 | 问题卡、最近邻与反证、可证伪假设、资源可得性 | 收缩问题或补查证据 |
| G1 数据准入 | 数据与标签能否支撑这个问题 | 来源卡、标签边界、质量与分组审计、曝光史 | 补源、降级任务或保留探索性 |
| G2 原理与评分 | 实现和测量是否正确 | 手算例、极限与反例、独立复算、评分边界 | 修代码、测量定义或模型假设 |
| G3 基线 | 对照是否适用、有竞争力且公平 | 复现说明、训练覆盖、开发选择、信息及预算表 | 补齐或调整主张 |
| G4 开发小试 | 新机制是否提供增量信息，规模是否可承受 | 开发区比较、消融、失败诊断、功效或精度及费用估计 | 改最小机制或接受负结果 |
| G5 协议冻结 | 哪些决定将不再依据正式结果改变 | 划分、参数、代码、模型、知识及分析规则快照 | 先补决定，不边测边选 |
| G6 正式运行 | 能否完整执行并保留失败 | 每例记录、原始输出、异常与费用账、输入输出绑定 | 分类恢复，缺陷变更按协议处理 |
| G7 分析与论文 | 数据能支持什么发现与领域解释 | 独立复算、主张证据表、全文、图源、引用对应 | 修分析或收缩结论 |
| G8 投稿与修回 | 材料、作者和版本是否一致 | 模板检查、最终文件、授权与真实回执、修回记录 | 明确待办，不冒称投稿完成 |
| G9 归档与复用 | 下一位研究者能否复现和接续 | 清单、环境、获取说明、失败与决策史、复用边界 | 补齐必要依赖 |

阶段是证据依赖，不要求所有研究机械使用同一任务数量。没有学习模型时，G3可对应成熟理论、数值方案或实验装置；没有确认性测试时，明确探索性设计，不虚设“盲测已通过”。

## 推进中的三个循环

**研究循环：**从观察、困惑或假设出发，按[证据反馈](证据反馈与变更控制.md#探索中的短循环)选择检查、更新理解并决定下一步。G0形成前可先探索，阶段退出仍需表中的证据；不同验证层次见[实验与复现](实验运行与复现.md#从最小检查走向目标条件)。

**执行循环：**选择依赖已满足的任务 → 写清输入输出和范围 → 实施 → 自检 → 按风险复核 → 登记结果 → 解锁下游。困难不等于阻塞，真正依赖缺失才标阻塞。

**写作循环：**主张 → 数据与来源 → 领域解释 → 图表 → 同行可读性 → 版式。科学内容变化返回分析；排版变化只重建受影响稿件，不重跑无关实验。

## 最小运行方式

小项目可用一份协议、一份任务账本、一份数据索引、一份运行记录和一份主张证据表开始。数据量大、多人协作或正式测试时，再增加分组清单、冻结快照、独立复核及恢复工具。目录和文件数量不作为研究进展指标。
