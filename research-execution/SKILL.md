# 研究执行技能

自包含技能，随 research-max 技能集分发使用。覆盖从研究方案到可复现证据的执行域：接手或启动项目、数据准入、任务推进、探索与变更、实验运行、结果诊断、归档复用。核心判断：领域问题、可观测量、数据真值和原理放在方法包装之前；方案转为有依赖、输出和验收条件的任务；开发区做最小可证伪改动，冻结后不按正式结果挑配置；负结果按原分母保存；文件存在或哈希匹配不证明科学正确。

| [templates/](templates/) | 空白模板：数据与划分卡、任务与验收、实验协议与冻结单（含探索记录）、主张与证据表、交接与修回、项目骨架 |

## 可选执行方式

仅当用户指定具体任务采用跨 Harness 协作时，读取[跨Harness任务执行](references/跨Harness任务执行.md)。任务长度、研究类型、项目文件和旧记录不触发派发；讨论、普通执行和查询继续按当前任务正常处理。本技能仍可按需发现，不因该模式改为只能显式调用。桥接安装与CLI见仓库顶层 integrations/claude-code，先核对真实授权及任务范围。

该模式支持在已有项目中选择继续执行或仅交叉核查已完成模块；默认一次主审、必要的局部回验，审核意见的快速核实合并进修回，不固定增加第三轮。具体规则与[接入模板](templates/现有项目跨Harness接入.md)按需读取。

用户指定任务采用GitHub记录并开始执行时，另读[GitHub模块记录](references/GitHub模块记录.md)及[空白接入模板](templates/GitHub记录接入.md)。用一个派生总览与模块PR记录推进，复用既有审核，通过后按授权自动合并；不因计划确认、普通执行或加载技能而推送。该能力独立于跨Harness，具体Git/GitHub CLI接口由库顶层integrations/github维护。

### 各文件一句话要求

以下为速览，执行时读 references/ 原文。

**流程与关卡**：接手先建事实入口（目标授权/方案/任务状态/数据入口/版本清单，冲突登记不静默择取）；每阶段回答"能做什么/凭什么算完成/未通过退回哪"；研究循环从观察困惑假设出发按证据反馈短循环推进，G0 形成前可先探索。

**数据准入**：七项准入（来源合法、用途一致、标签边界、质量审计、分组隔离、曝光史、记录完整）；先分组再划分；受控生成记录指令与种子；知识与经验隔离，研究记忆不作为被测知识。

**方案落地**：方案转为有依赖、输出与验收条件的任务合同；Markdown 任务卡直接维护唯一状态，旧 JSON 项目兼容而不双写；验收强度与风险匹配；接受、冻结、交付分别记录不互相顶替。

**证据反馈**：探索短循环回答五问（不懂什么/事前预计/能区分哪些解释/实际观察/判断如何改变），事前预期不可事后补造；调整分三级（下一项检查/机制假设/研究问题）＋五决定（继续扩大/补判别证据/转向收缩/暂缓停止/接受负结果）；正式测试后的变更按分流表处理。

**协作与接续**：人负责研究价值与关键取舍，AI 提供可核查备选并可质疑；四类追问（依据在哪/为何优先查这/还有什么解释/如何最小代价区分）；AI 自评与多模型意见不认证科学正确；接续必须交代游标、授权与未决事项。

**实验运行**：原理与接口先过手算例、极限反例、独立复算；强基线公平适配；最小检查→开发比较→目标条件验证三层次各有"不能直接推出什么"；小试估计功效精度费用；冻结划分/参数/代码/模型/知识/分析规则；正式运行每例记录、异常分类恢复。

**统计诊断**：先核对分母再解释分数；同分按定位顺序排查（实现/数据/评分/随机性）；统计推断与外推不越证据；统计报告完整性清单逐项核对（效应量、区间、预定水平、多重比较、缺失数据、分方法最小项）；从数字到领域解释；负结果与主张分开入账。

**归档复用**：清单绑定哈希、新版本另存；录用、校样、发表版本分存并关联预印本，发表后核对可用性声明与勘误记录；跨环境复现须有代表性；经验复用记录适用范围、正反证据和撤销条件，未通过经验不进入有效运行知识。

## 场景流程

| 场景 | 做法 |
|---|---|
| 接手项目或新会话 | 按[流程与关卡](references/流程与关卡.md)先建立事实入口，核对版本与授权；用[交接与修回模板](templates/交接与修回模板.md)交代游标 |
| 新项目启动 | 可用[项目骨架](templates/项目骨架/README.md)或 `scripts/research_infra.py init` 起步；允许在 G0 完成前从观察或困惑开始探索，形成正式主张前补齐 G0 证据（选题方法见 research-topic 技能） |
| 定好方案开始执行 | [总体计划模板](templates/项目骨架/PLAN.md) → [模块任务卡](templates/任务与验收.md) → 按证据依赖执行；状态标签用于检查接续，不是暂停指令 |
| 执行中计划发生调整 | [计划调整后同步任务](references/证据反馈与变更控制.md#计划调整后同步任务)：判断影响、局部更新ID与依赖、核对验收依据、完成修订同步；无关工作继续 |
| 从现象探索、判断下一项检查或调整方向 | [证据反馈](references/证据反馈与变更控制.md#探索中的短循环)＋[实验层次](references/实验运行与复现.md#从最小检查走向目标条件)；轻量记录用[实验协议的探索记录](templates/实验协议与冻结单.md#探索记录按需填写)，不逐次工具调用填表 |
| 与 AI 澄清理解、质疑依据或比较解释 | [理解与判断分工](references/协作与接续.md#理解质疑与判断分工)四类追问 |
| 同分、失败或需要改方案 | [统计诊断](references/统计评价与结果诊断.md)同分定位；[变更分流](references/证据反馈与变更控制.md#正式测试后的变更分流) |
| 冻结或正式测试后想换配置、提示词 | 走[正式测试后的变更分流](references/证据反馈与变更控制.md#正式测试后的变更分流)：原测试即成开发信息，新配置须用未曝光测试重测或明确降为探索性结果 |
| 交付研究产物、换人或结题 | [归档与复用](references/归档与复用.md)；写作与投稿走 paper-writing 技能 |

## 贯穿红线

- 领域问题、可观测量、数据真值和原理放在方法包装之前；AI/LLM 是否加入以增量信息及公平对照决定。
- 事前预期不可事后补造；正式协议冻结后不根据测试表现挑选配置。
- 失败、回退和负结果按原分母保存；不删失败样本、不挑有利子集、不为"去 AI 化"删局限。
- 数字、区间、公式、图表和主张可追溯；文件存在或哈希匹配不证明科学正确。
- 维护操作不污染证据：额外投入的收益不归因于新机制，环境变更不冒充实验效果。
- 完成时交付实际文件、验证范围、必要缺口和下一步入口；只在取得真实回执后记录已投稿。

## 交付闸门

1. **可选机械检查**（本地运行，board 默认输出 Markdown，其余输出 JSON；退出码 0=机械通过 / 1=不一致 / 2=输入或读取错误）：

   ```
   python scripts/research_infra.py init --dest <空目录> --name <研究名称>
   python scripts/research_infra.py check --root <项目目录>
   python scripts/research_infra.py board --root <项目目录>
   python scripts/research_infra.py snapshot --root <项目目录> --id <快照ID> --kind protocol --files <明确列出的文件>
   python scripts/research_infra.py verify --root <项目目录> --manifest snapshots/<快照ID>.json
   ```

   `init` 只接受不存在或全空目录，默认 Markdown，`--task-format json` 保留旧格式；`check` 核对任务依赖/承接关系/状态/计划同步/验收产物与任务要求绑定；`snapshot` 只创建不覆盖，保存明确列出文件的 SHA256；`verify` 只复核清单内容相同。工具通过只代表机械项通过，不证明科学正确、清单完整或复核独立；`--files` 不支持通配符，路径不得越出项目。
   Markdown 固定字段、回执和 hash/basis/board 使用见[Markdown任务格式](references/Markdown任务格式.md)。check/board/snapshot 用 `--tasks` 指定自定义任务源；双源不猜优先级。可直接阅读与编辑任务 Markdown，无须运行工具。
2. **实质审查**：阶段退出按 G 表"最小退出证据"逐项核对；费用、样本分母、统计正确性、投稿样式不由此工具审计，由研究者实质审查。
3. **结题归档**：按[归档与复用](references/归档与复用.md)交付清单并绑定哈希。

## 边界

- 适用于计算、仿真、实验、观察与理论研究的过程管理；按研究类型选用验证方式，伦理审批、仪器校准等学科专项在对应项目填写。
- 选题调研与论文精读见 research-topic 技能；论文写作、图表与投稿修回见 paper-writing 技能；非论文报告见 report-writing 技能——均按名使用不复制规则。
- 迭代是否继续、何时止损、探索额度与重写计价见 effort-guard 技能；本技能的费用表、冻结规则与统计要求不因此改变。
- 模板保持空白，未知项如实标注；项目骨架不得从其他项目复制 ACCEPTED、预算授权、作者身份或冻结状态。
- 规则在本目录单一维护；写作域模板（稿件与图表审查单、正文与附录规划、范文学习卡）随 paper-writing 技能维护，本技能按名提及；`submission_profile.json` 空白模板随本技能项目骨架分发，paper-writing 技能按名使用。
