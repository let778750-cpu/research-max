# 正文、附录与补充材料的分工

本文件维护A1—A7：是否设置附录、材料放在哪里、怎样组织和定位、怎样保持整套稿件一致。核心原则是：**判断结论所需的信息在正文中清楚呈现，核验和复现所需的细节在整套材料中完整可达。** 附录不按页数评优，也不预设每篇论文都必须具备。

章节论证与语言见[W项](论文组织与语言规范.md)，数学与引文见[M项](公式与引用规范.md)，图表和实际提交版式见[F项](科研图表与模板验收.md)。本文件只维护材料分工，不重述这些详细规则。规划时取用[空白模板](../templates/正文与附录规划模板.md)，交付时使用[统一审查单](../templates/稿件与图表审查单.md)。

<a id="a1"></a>
## A1　按证据需要判断是否设置

先确定当前刊会、文章类型和投稿阶段对材料的明确要求，再检查论文留下了哪些核验或复现需求。判断顺序如下：

1. 投稿要求指定材料或载体时，按其要求准备；要求“必须报告某项信息”不自动等于“必须另设附录”。
2. 理解和评价主结论离不开的假设、机制、评价含义、关键结果及限制，应在正文中充分说明。需要压缩时先形成可判断的概括，再将详细推导或记录放到允许的补充载体。
3. 完整证明、详细协议、参数、额外分析等确有核验价值，但展开会打断主线时，设置附录或补充材料，并建立准确入口。
4. 内容短且正文已充分覆盖，或没有与主张相关的新增材料时，可以不设附录，记录理由即可。不为满足模板而补造实验、堆放教科书背景或复制正文。

区分“信息是否必要”和“是否必须叫附录”。一份短稿可在正文交代全部信息；复杂研究也可由正文、期刊Methods、补充文件和公开工件共同承载。正文自足是足以理解和评价主结论，不等于在正文容纳全部复现步骤。应同时检查两条路径：只读正文能否判断结论；沿已提交材料能否找到核验和复现细节。

页数有限不能成为隐藏关键条件的理由。若必要论证无法在当前格式内成立，应收缩主张、重组稿件或选择适合的文章类型；不能默认评审会阅读全部附录。正文概括必须与原始证据相符，缺失的研究步骤不能用“详见附录”掩盖。

<a id="a2"></a>
## A2　按投稿渠道区分载体

| 载体 | 主要用途 | 项目中需核实的要求 |
|---|---|---|
| 文末附录 | 与正文一起阅读的证明、协议、更多分析 | 是否允许、与正文是否合并PDF、位置、页数口径与编号 |
| 独立补充信息或材料 | 较长方法、补充结果、说明文档及多媒体 | 文件分类、格式大小、提交入口、截止时间、是否审阅及发布 |
| 期刊Methods | 期刊规定的方法部分 | 所属稿件结构、字数口径、引用及数据代码声明位置 |
| Extended Data | 期刊定义的扩展图表 | 是否设此类别、数量、尺寸、图注、编号及主文引用方式 |
| 数据与代码工件 | 可执行实现、机器可读数据、配置和环境 | 匿名与访问权限、固定版本、许可、README及长期可达性 |

这些载体承担不同职责，不能互相改名代替。Methods不自动算附录；Extended Data也不等同于所有期刊的Supplementary Figures。以本次实际刊会要求为准，不能从Nature推广到全部Nature Portfolio期刊，更不能推广到所有SCI期刊。

在规划表记录官方来源、访问日期、适用年份和投稿阶段，并区分明确要求与作者自行选择。正文页数、附录页数、参考文献口径、图表与公式编号、匿名要求和文件合并方式逐项确定。首投、修回与录用终版可能不同；来源冲突记入项目根目录`submission_profile.json`（模板随 research-execution 技能的项目骨架分发）的`requirements_trace`与`unresolved`，保留依据，不增设平行配置系统。

本技能只提炼组织原则，不固定任何刊会的页数、文件大小、章节顺序或引用编号；投稿时以当前刊会官方要求重新核对。

<a id="a3"></a>
## A3　按主张与证据分配内容

| 内容 | 正文应保留的判断依据 | 可展开到附录或补充材料的内容 |
|---|---|---|
| 理论与机制 | 问题、命题、适用假设、创新步骤及证明思路 | 完整证明、引理、推导细节、边界计算 |
| 数据与标注 | 来源、范围、独立单位、划分原则、关键筛选与质量证据 | 完整筛选流程、分项计数、标注指令、争议处理及数据说明 |
| 算法与系统 | 输入输出、核心计算、模块关系、停止失败条件及贡献所在 | 完整伪代码、配置、依赖、提示词、工具协议和运行说明 |
| 评价与统计 | 指标含义、主要计算规则、比较设计、分母、关键不确定性 | 完整公式、具体算例、逐组结果、评价者校准与敏感性分析 |
| 结果与局限 | 主比较、决定性证据、重要例外与影响结论的负结果 | 完整结果矩阵、次要消融、诊断图、失败分类及代表案例 |

表格按研究贡献使用，不是固定的搬移清单。若新评分器、数据构建方式、提示或约束本身构成核心创新，正文须解释其关键内容；若稳健性分析决定主张是否成立，正文须报告其主要结果。影响判断的内容可以在正文概括、在附录完整展开，但不能仅以标题或空泛结论占位。

以主张与证据表（随 research-execution 技能分发）为主张入口。规划表引用同一主张的位置或已有标识，不复制一份可独立变动的主张账本。每项补充材料都应对应研究问题、论证或复现任务；无对应关系时判断是否移入研究记录或删去。

大型数据表、原始输出和代码优先放入合适的机器可读工件，并在稿件中解释字段、获取方式、版本和使用入口。代码链接不能替代方法说明；完整文字说明也不能替代实际可运行文件。隐私、许可或匿名要求限制公开时，如实说明可用范围、获准的访问途径及其对复现的影响，不声称完全开放。

<a id="a4"></a>
## A4　每节围绕一个核验问题组织

标题应让读者判断这一节能解决什么，例如“数据筛选与排除规则”“评分边界案例”“不同工况下的完整结果”。避免大量同名“更多细节”小节，也不强制全部论文套用相同的附录顺序。

章节开始说明对应哪一项正文方法或主张、为什么需要本节、实际覆盖范围。随后按材料性质组织：

- **推导与证明**：给清命题和假设的对应关系、必要定义、推导过程及适用边界；符号和数学核验遵循M1、M2。
- **实验与数据协议**：写到实际可执行和可检查的程度，记录关键条件与选择依据；已有数据、实验和统计规则继续在原权威文件维护。
- **提示词、算法与接口**：区分固定指令、动态输入、示例、允许工具和输出要求；提供实际版本，并解释它们怎样参与研究。长文本保持可复制，不仅给截图。
- **补充结果与案例**：交代问题、比较条件及选择依据，呈现结果并说明它对正文主张的支持、限制或修正。不能只堆图表，也不能用少量成功个案替代总体评价。

可独立阅读不等于重复整篇正文。必要定义可简要重述或准确回指；同一符号不得在附录中暗换含义。协议、指令与数据清单不强套实验论文的“结果—讨论”结构。

<a id="a5"></a>
## A5　正文与补充材料建立双向定位

正文在提出问题、使用方法或解释结果的适当位置，说明补充材料的用途并指到具体节、图表或文件。结果类内容还应概括关键发现；协议类内容交代其用途和范围即可，不编造“主要发现”。附录开头回指对应正文位置，并说明增补了哪一层信息。

使用稳定标题与编号，按实际投稿格式保持交叉引用一致。较长、跨多个主题的附录增加目录或阅读导航；不以固定页数阈值判定。每个提交文件应有清楚的名称、内容说明和稿件内入口。若格式使用独立参考文献，或要求续编号，均按当前渠道执行，引用核验仍遵循M3、M4。

以下四组是**表达结构示例，全部方括号均为待填项**，不构成任何真实研究记录；不要求逐句照搬。

### 示例一：推导与证明

> 正文：在［假设及范围］下，［命题］成立。关键步骤是通过［机制或变换］将［问题］转化为［可处理形式］；完整证明及［边界情形］见附录［编号］。
>
> 附录开头：本节给出正文［命题编号］的证明，沿用［符号与假设位置］。下文先处理［关键步骤］，再检查［边界］；结论不涉及［未覆盖条件］。

### 示例二：数据与标注

> 正文：样本来自［来源与范围］，按［独立单位］划分，以［关键规则］排除［不适用样本］。质量检查得到［已核验发现］。完整计数流程、标注指令与争议处理见附录［编号］。
>
> 附录开头：本节补充正文［数据小节］。表［编号］按实际处理阶段列出输入、保留和排除数量及理由；随后给出标注者实际使用的［指令版本］与裁决流程。

### 示例三：算法与提示词

> 正文：［模块］接收［输入］，依据［核心规则］产生［输出］，并在［失败条件］下采取［处理方式］。完整指令、动态输入字段和调用配置见附录［编号］。
>
> 附录开头：本节对应正文［模块］。固定指令与逐样本输入分别列出；［示例］是否参与正式评测、［工具］的权限及［输出］的解析规则按实际版本说明。

### 示例四：稳健性与负结果

> 正文：在［条件］下，［关键发现及区间］；在［例外条件］下，该结论不再成立。完整条件矩阵与失败分类见附录［编号］。
>
> 附录开头：本节检验正文［主张］对［条件变化］的依赖。按［预定规则］报告完整结果和失败案例；其中［发现］使结论的适用范围收缩为［范围］。

<a id="a6"></a>
## A6　保持证据完整与跨材料一致

正文、附录、图表、代码和数据引用应指向同一研究版本。按既有规则核对数值、分母、独立单位、划分、统计口径、符号、单位、参数与结论强度；同名表格或结果多处出现时说明汇总关系，并同步修订。版本或数值冲突先定位原因，不选择更有利的一份作为正文结果。

补充分析如果改变主要排名、暴露关键失效或削弱机制解释，应更新正文结果、讨论及受影响的摘要和结论。篇幅压力、结果不利或图像不美观都不改变其证据地位。探索性分析按实际过程标明，不能因写入附录就变成预先设计的确认性实验。

检查正文指向的材料是否实际提交或可按许可访问；缺页、错误文件、失效链接、未发布配置及只存在于本机的路径均需记录影响。材料尚未准备好时保留待办；对于当前必须提供的证据，不能以“待补”状态宣布投稿材料齐备。

完整性不是把所有运行日志塞入PDF。保留与研究有关的证据、选择规则和工件入口；未完成或失败的复现应按真实状态说明。附录详细、代码开放、机械检查通过分别是不同事实，均不直接证明科学结论成立或复现成功。

<a id="a7"></a>
## A7　精简后按整套提交件验收

先删去不服务研究问题的背景、重复正文、无选择依据的成功案例及缺少解释的结果堆积。确有教学或领域背景需要时保留必要解释并标明用途，不以“附录不限页”无限扩展。

图表可读性和源文件转换沿用F项；附录、独立补充文件及不同载体按各自实际提交尺寸检查。公式、图注、表注、页码、目录、链接和参考文献不得因位于附录而降低检查标准。匿名检查覆盖附件、文件名、元数据及链接的实际访问方式。

材料稳定后，使用统一审查单分别记录内容、表达及最终文件检查，将每一轮实际提交的正文、附录、声明与工件版本共同归档，流程见[投稿与修回](投稿与修回.md)。普通修订只复核受影响内容和关联位置；切换刊会或投稿阶段时重新核对载体要求。

是否适合不设附录、是否支撑正文判断、能否沿证据入口核验，以及最终材料是否一致，是实际验收问题。模板填写量、附录页数和打勾数量不是质量证明。
