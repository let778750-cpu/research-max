# 论文写作技能

自包含技能，随 research-max 技能集分发使用。目标读者是本领域同行：让他们看清研究解决什么问题、为什么这样设计、证据是否充分、结果意味着什么。全文按真实研究组织，AI作为方法中的具体能力出现。

| 目录 | 内容 |
|---|---|
| [references/](references/) | 规则全文：W1—W10论文组织与语言、M1—M4公式与引用、F1—F7图表与版式、F8—F14科研绘图生产、A1—A7附录与补充材料、投稿与修回、偏好表示例 |
| [templates/](templates/) | 写作空白模板：正文与附录规划、稿件与图表审查单、范文拆解与句式学习卡、图形规格卡与绘图样式示例、审稿意见路线图 |
| [scripts/](scripts/) | writing_lint.py写作质量机械自检：节奏／内容守恒／中文PDF排版三模块，本地运行，不联网、不调用模型 |

项目级共享模板（主张与证据表、交接与修回模板、submission_profile.json）的唯一权威在 research-execution 技能，本技能按名使用、不复制副本。

动笔前先判断文体：投给期刊会议的稿件用本技能；报告、记录、评审等非论文文体不在范围内，另按对应文体规范执行。科研真实性要求（语言润色不替代补证、负结果如实入账、不虚构数据与引文）适用于所有文体。

### 各规则一句话要求

以下为规则标题速览，执行时读references/原文。

**W 论文组织与语言**：W1先建立一条能由证据回答的研究主线（核对领域问题—缺口—机制—对照—允许的结论，建立主张与证据表，模板随 research-execution 技能分发）；W2题名概括实际研究，不做组件清单；W3引言形成问题、现状、缺口和研究重点的递进；W4原理部分讲清为什么可以这样计算；W5数据与实验方案部分讲清凭什么检验研究问题；W6结果按研究问题组织，突出关键发现；W7讨论与结论回答为什么这样设计、有什么意义；W8摘要最后定稿，概括完整研究；W9自然、具体的科研语言，含[结构与节奏的模板化控制](references/论文组织与语言规范.md#结构与节奏的模板化控制)与[范文拆解与句式迁移](references/论文组织与语言规范.md#范文拆解与句式迁移)；W10按影响修订，完成内容回归检查。

**M 公式与引用**：M1符号、单位与可编辑数学；M2公式说明从假设到实际计算；M3引文支持具体论断；M4正文标签与参考文献排布。

**F 图表与版式**：F1图的类型、位置和科学关系；F2定量结果图由确定的数据生成；F3图源、文字与最终清晰度；F4三线表以信息结构决定列宽；F5每个图表前引入，后解释；F6真实模板与最终提交版本逐项对照；F7中文PDF排版验收：两端对齐与行首禁则。

**F 科研绘图生产**：F8图形契约先于代码；F9图型选择与四原型；F10配色与无障碍；F11字号、线宽与刊印尺寸；F12多面板证据架构；F13导出与可编辑性；F14渲染后自检与图注统计最小项。生产完成回F1—F7与F6验收。

**A 附录与补充材料**：A1按证据需要判断是否设置；A2按投稿渠道区分载体；A3按主张与证据分配内容；A4每节围绕一个核验问题组织；A5正文与补充材料建立双向定位；A6保持证据完整与跨材料一致；A7精简后按整套提交件验收。

## 写作流程

| 场景 | 做法 |
|---|---|
| 全文重写 | 先核对主张与证据表（随 research-execution 技能分发），按W1确定章节职责；推荐顺序为原理与方案、结果、讨论，再校准引言与题名，最后定稿摘要；随写作检查公式（M）与图表（F），内容稳定后进入版式（F6） |
| 局部修改 | 只读取对应规则及受影响上下文；改指标、比较对象或研究主张时回到相关证据，同步摘要、图表和结论（W10） |
| 表达练习 | 按W9选取与本研究适配的范文（适配性与科学质量优先于刊名和热度），用[范文拆解与句式学习卡](templates/范文拆解与句式学习卡.md)执行小循环：拆解→抽象功能与槽位→离开原文自写→对照检查→批判修订；正反例分布在W3、W5—W9 |
| 附录规划 | 按[A1—A3](references/附录与补充材料规范.md#a1)判断必要性、投稿载体和内容分配，再填[正文与附录规划模板](templates/正文与附录规划模板.md) |
| 新建或重做结果图 | 先填[图形规格卡](templates/图形规格卡.md)（F8），按F9—F13生产、F14渲染后自检，再回F1—F7与F6验收；样式取值按项目配置域登记，示例见[figure_style.template.mplstyle](templates/figure_style.template.mplstyle) |
| 审稿修回 | 意见按科学、方法、统计、数据、表述、版式分类，逐条列原意见、判断、行动、证据、修改位置及状态；接受、部分接受与不同意均给可核对依据，只改措辞不改实质的“表面服从”登记为未解决。看过测试后改变方法需新的确认性数据或明确探索性定位。详见[投稿与修回](references/投稿与修回.md)；修回状态记录在 research-execution 技能的交接与修回模板 |

## 贯穿红线

- 语言润色不能替代补证；关键实验缺失时如实留待补内容（W1）。计划步骤不能用过去时写成已执行（W5）。
- 失败、未解决案例与重要负结果按预定规则入账，不被最高分掩盖；不同场景指标不同则分别陈述（W6）。
- 把“与机制相符”改成“证明机制”、把“计划实现”改成“已实现”是科学内容变化，不是润色（W10）。
- 不虚构审稿人对白、空泛自夸与重复辩解；不为规避AI检测刻意造错、打乱结构或隐藏辅助使用（W9）。
- 不搬用他人独特表述、论证或发现再以同义替换掩饰；借鉴按M3引用（W9）。
- 正文保留足以理解和评价主结论的信息，不以“详见补充材料”回避关键条件（A1）；页数有限不能隐藏关键条件，必要时收缩主张。
- 定量结果图从冻结或独立核验的结果确定性绘制；图像生成工具不承担精确数据、误差线和数值标签，不补随机数字（F2）。
- 绘图从核心结论出发选最少面板，不从模板或输入表出发（F8）；自动渲染检查通过不等于视觉验收通过，字号与对齐以导出件实测为准（F14）。
- 图像识别核对版式会产生幻觉，中文PDF排版验收一律以文本提取为准（F7）。

## 交付闸门

1. **机械自检**：`scripts/writing_lint.py`三模块（建议设置`PYTHONUTF8=1`；layout依赖PyMuPDF）——

   ```
   python scripts/writing_lint.py rhythm  <稿件.md>
   python scripts/writing_lint.py parity  <原稿.md> <新稿.md>
   python scripts/writing_lint.py layout  <成品.pdf> --right <版心右缘pt> [--header <页眉首行文本>]
   ```

   `rhythm`查节奏与元话语（对应W9量化参考带），`parity`查URL／引文编号／数字／引语逐字守恒（对应W10），`layout`查行首禁则、右缘越界与齐右（对应F7）。判定两级：警告＝提示人工复查，失败＝按规则不得交付；通过只代表机械项通过。工具回归使用已知预期的正反例；普通稿件按实际结果判断，不预设原版失败或重写版通过。
2. **三遍审查**：用[稿件与图表审查单](templates/稿件与图表审查单.md)依次检查内容与科学一致性、表达与数学与文献、图表与最终投稿件；按“问题位置—依据—修复—验证”记录，不能以打勾代替实际审阅。
3. **最终版式**：单一权威稿加受控转换链；最终PDF逐页查看（F6），样式对照项目根目录的 submission_profile.json（模板随 research-execution 技能的项目骨架分发）与[偏好表示例](references/偏好表示例.md)。没有回执不写已投稿。

## 边界

- 适用于实验型和方法型研究论文；综述、纯理论或学科特定文章按职责调整结构，科研真实性要求保持。
- [偏好表示例](references/偏好表示例.md)的具体数值与样式来自示例项目，不是所有刊会的统一规定；新项目按用户当前选择和实际模板填写`submission_profile.json`（模板随 research-execution 技能分发），空白字段保持待填，不虚构。
- 研究方案、实验执行、数据管理与流程协作不在本技能范围。
- 规则阈值为初版标定（如W9量化参考带），随使用修正。写作规则在本目录单一维护；项目级共享模板的唯一权威在 research-execution 技能，本技能只按名提及、不复制副本，修订时不得新增对外部文件的依赖。
